# 语音助手JSON朗读问题修复

## 问题描述
语音助手在执行设备控制时会朗读JSON格式的控制命令，导致用户体验不佳。例如：
- 用户："开启风扇"
- 语音助手朗读："好的，正在为你开启风扇 大括号 引号action引号 冒号 引号toggle_relay引号..."

## 解决方案
在语音助手的系统提示词中添加明确的指令，要求AI模型在语音朗读时跳过JSON内容，只朗读自然语言描述。

## 修改文件

### 1. `components/realtime-voice-orb.tsx`
- 修改默认`instructions`参数，添加"不要朗读JSON"的指令
- 在`enhancedInstructions`中的设备控制能力部分，添加详细的语音输出规则
- 强调：JSON命令放在回复末尾，语音朗读时完全跳过JSON部分

### 2. `lib/xiaozhi/realtimeClient.ts`
- 更新默认`instructions`配置，添加"不要朗读JSON"的指令

### 3. `components/xiaozhi/FloatingXiaozhi.tsx`
- 在自定义的`instructions`中添加"语音输出规则"部分
- 明确说明不要朗读包含大括号、引号、冒号等JSON符号的内容

## 关键指令内容

```
重要：当你需要输出JSON命令时（如设备控制、定时任务、页面导航），
请将JSON放在回复末尾，但在语音朗读时完全跳过JSON部分，只朗读自然语言描述。
绝不要朗读任何包含大括号、引号、冒号等JSON符号的内容。
```

## 预期效果
- 用户："开启风扇"
- 语音助手回复文本："好的，正在为你开启风扇 {"action":"toggle_relay","device":6,"value":1}"
- 语音助手朗读："好的，正在为你开启风扇"（不朗读JSON部分）
- 系统自动解析JSON并执行设备控制

## 测试建议
1. 测试设备控制命令（继电器、LED、摄像头云台）
2. 测试定时任务创建
3. 测试页面导航
4. 确认语音输出中不包含JSON符号的朗读

## 注意事项
- 这个修改依赖于AI模型正确理解和执行系统提示词
- 如果模型仍然朗读JSON，可能需要进一步优化提示词或在客户端进行后处理
- 当前实现是通过提示词工程解决，没有修改音频处理逻辑
