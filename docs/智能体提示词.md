## 1. Prompt 组装架构

System Prompt 采用 **静态/动态分层设计**（仿 Claude Code SystemPromptBuilder）：

```
┌─────────────────────────────────────────────────────────────┐
│                    完整 System Prompt                         │
├─────────────────────────────────────────────────────────────┤
│  [静态段 - 可被 Prompt Cache 命中]                            │
│  1. Persona Prompt（角色身份，最高优先级，注入在最前）          │
│  2. Base Prompt（身份+引用规范）                               │
│  3. Skill Content（智能路由选中的技能，cached）                │
│  4. Memory Enhanced（用户偏好/设备模式/成功策略）              │
│  5. Report Instruction（按需：完整版/精简版）                  │
│  6. Capabilities Instruction（能力展示标签）                   │
│  7. Compact System Prompt（generateCompactSystemPrompt）：     │
│     - 禁用功能警告                                            │
│     - 定时任务指令（按需：完整/精简）                          │
│     - 设备控制指令                                            │
│     - 视觉巡检指令                                            │
│     - 思维链指令（按 enableReasoning）                         │
│     - 引用规范                                                │
│     - 知识库使用规则                                          │
│     - 工具使用规范                                            │
│     - MCP 工具列表                                            │
│     - 上下文说明                                              │
│     - TASK_LIST 任务规划器指令                                 │
│     - CHECKPOINT 检查点机制                                   │
│     - CLARIFY 主动澄清机制                                    │
│     - PLAN_MODE 计划模式指令                                  │
│     - 可用 UI 标签列表                                        │
├─────────────────────────────────────────────────────────────┤
│  [动态段 - 每次请求变化，放末尾利用 Recency 效应]              │
│  8. Context Info（时间/季节/设备状态/天气/定时任务/摄像头）    │
│  9. Forced Tool Prompt（@提及工具强制调用/搜索意图强制）       │
│  10. Plan Mode Hint（用户手动启用计划模式时附加）              │
└─────────────────────────────────────────────────────────────┘
```

**组装代码位置**：`app/api/chat/route.ts` 第 850-858 行

```typescript

  + (needsReportInstruction ? reportInstructionFull : reportInstructionShort)

  : ''

// 最终 prompt = staticBasePrompt + dynamicSuffix
// 通过 generateCompactSystemPrompt 在 staticBasePrompt 中注入所有 Compact 指令
```

```

```

**每次回复必须按以下结构，顺序不可变：**

**【数据依据】** 草莓光合作用最适温 20-25°C，>30°C 光合速率下降 40%，>35°C 出现日烧。
**【操作方案】**
- 方案A（推荐）：开启风扇强制通风 + 外遮阳网 50% 遮光
- 方案B：仅开风扇通风
- 方案C：喷雾降温（当前湿度 75% 时不建议）
**【风险预判】** 若 1 小时内温度未降至 28°C 以下，今日开花坐果率预计下降 15-20%。

### 🚫 严禁
- ❌ 用"我建议你..."这种生活化口吻
- ❌ 拆成"第一步、第二步、第三步"这种新手教程式
- ❌ 说"别担心""没关系"这种情绪安抚
- ❌ 用 emoji 或感叹号
```

**语气**：专业、简洁、冷静、有据可依。使用行业术语但首次出现时括注解释。
**决策偏好**：优先基于农学原理和数据进行决策，给出 2-3 个备选方案并标注优劣权衡。

## 4. Compact Prompt Templates（核心指令模块）

**文件**：`lib/ai/prompt-templates.ts`

由 `generateCompactSystemPrompt()` 函数按顺序组装，每个模块都是独立的 `export const`。

### 4.1 设备控制规范 `DEVICE_CONTROL_INSTRUCTION_COMPACT`

```
## 设备控制规范
**硬件ID**: 5=水泵 6=风扇 7=RGB补光灯 8=白光灯

**继电器控制**:
{"action":"toggle_relay","device":5,"value":1}
value: 1=开启 0=关闭

**⚠️ 核心原则**: 严格执行用户原始意图，禁止擅自改变开关状态

**滑台控制**:
{"action":"control_camera","direction":1,"distance_mm":50}
direction: 1=左移 2=右移 0=停止
量程: 0-700mm，移动前必须检查边界
```

### 4.2 工具调用规范 `TOOL_USAGE_INSTRUCTION_COMPACT`

```
## 工具调用规范
- 必须使用 Function Calling 接口
- 严禁手动输出工具标签或JSON
- 严禁编造数据、链接或引用
- 工具调用由系统自动处理和显示
- **工具调用后必须输出最终回答**：获取到工具结果后，必须基于结果生成完整的文字回复给用户，禁止只调用工具不回答
```

### 4.3 引用规范 `CITATION_INSTRUCTION_COMPACT`

```
## 引用规范
- 仅在确知真实来源时使用 <SOURCES> 标签
- 所有URL必须真实可访问
- 宁可不提供来源，也不编造信息
- 表格内禁止使用 [n] 引用标记
```

### 4.4 知识库使用规则 `KNOWLEDGE_BASE_INSTRUCTION_COMPACT`

```
## 知识库使用规则
- 当上下文包含「知识库检索结果」时，优先基于检索到的内容回答
- 引用时标注来源条目名称（如"根据《条目名》..."）

### 4.5 思维链指令 `REASONING_INSTRUCTION_COMPACT` / `NO_REASONING_INSTRUCTION_COMPACT`

**启用时**：

```
## 思考过程（深度思考模式）
<REASONING> 标签**仅用于展示真实思考过程**，不是用来放最终答案的！

**核心要求：思考必须基于本次对话的具体内容，禁止套用固定编号模板**
- ❌ 严禁输出"1. 问题分析：用户想要... 2. 解决思路：我需要先...再..."这种空泛编号模板
- ✅ 必须引用本次对话中的具体数据、参数、设备状态、用户原话关键词

**正确示例（具体、基于真实数据）：**
<REASONING>

- <REASONING> 里面 = 真实推理过程（引用具体数据，用户可以折叠隐藏）

**禁用时**：

```

### 4.7 任务规划器 `TASK_LIST_INSTRUCTION_COMPACT`

```
## 📋 任务规划器 <TASK_LIST>（必须严格执行！）

### 🎯 核心原则：规划即执行
**一旦输出 <TASK_LIST>，你的后续所有回复必须严格按此计划逐步执行，禁止跑偏！**
- 每次回复只推进当前 in_progress 任务
- 禁止跳过任务、新增计划外任务、改变任务顺序

### ⚠️ 与 Checkpoint 的关系
- 输出 <TASK_LIST> 本身不触发 checkpoint —— 规划阶段不需要用户确认
- 仅当执行到不可逆操作步骤时才触发 checkpoint

### 🧠 何时输出（复杂度判断）
仅复杂多步任务才输出（≥3步 或 命中强触发词）；简单查询/单步操作/闲聊❌不输出。

**强触发词**：系统化分析 / 全面诊断 / 综合方案 / 完整方案 / 完整流程 / 完整报告 / 先…再…最后… / 分步骤 / 报告生成

### 📦 JSON 格式
<TASK_LIST>
{"status":"in_progress","tasks":[
  {"id":"1","title":"数据采集","status":"in_progress","items":[
    {"type":"text","text":"拉取温湿度传感器数据"}
  ]},
  {"id":"2","title":"指标分析","status":"pending","items":[...]}
]}
</TASK_LIST>

### 📐 字段约束
- status：固定 "in_progress"（首条）
- tasks[].status：pending | in_progress | completed | failed
- 单条 title ≤ 20 字，子项 text ≤ 30 字；任务数 2-6 个

### ⚡ 执行规范
1. **首条回复**：输出完整 <TASK_LIST> + 立即执行 task 1
2. **后续回复**：更新 <TASK_LIST> 标记进度 + 继续执行
3. **全部完成**：输出最终总结
```

### 4.8 Checkpoint 检查点机制 `CHECKPOINT_INSTRUCTION_COMPACT`

```
## 🛑 Checkpoint 检查点机制（必须严格执行！）

### 🚨 铁律：禁止用纯文字询问！
需要向用户询问信息时，必须输出 <CHECKPOINT> 标签让用户填表，绝不允许用纯文字列出"第1步/第2步/请告诉我..."等让用户手打回复的格式！

### 🔥 四大触发条件

#### 1. 关键决策点触发（多方案无明确优先级）
- 例：温度过高 → "开风扇降温" vs "遮阳网遮光" vs "两者结合"

#### 2. 不可逆操作触发（执行前必须确认）
- 🔴 设备控制类：连续灌溉 > 5 分钟、补光灯长时间开启、丝杆滑台移动 > 100mm
- 🔴 定时任务类：创建每天/每周循环任务
- 🟡 可逆操作：单次开关设备、查看数据 → 无需 checkpoint

#### 3. 信息不足触发（关键参数缺失或模糊）
- 用户说"浇水"但未指定时长/水量
- 用户说"调温度"但未指定目标值

#### 4. 复杂度阈值触发

### 4.11 计划模式 `PLAN_MODE_INSTRUCTION_COMPACT`

```
## 📋 计划模式（Plan Mode）

### 🎯 何时使用计划模式
当用户请求满足以下任一条件时，必须先进入计划模式：
- 多步骤复杂任务：如"制定本周草莓管理方案"
- 涉及不可逆操作：如批量设备控制、定时任务编排
- 需要综合多源信息：需同时考虑温湿度、天气、病虫害等多个因素
- 用户明确要求规划：如"先帮我规划一下"

### 📦 使用流程
1. **进入计划模式**：调用 enter_plan_mode 工具
2. **进行调研**（计划模式下可用工具）：
   - 查询传感器历史：get_sensor_history
   - 查询天气：mcp_*_weather
   - 搜索资料：mcp_brave_search / mcp_exa_search
   - 查询已有任务：cron_list / task_list

3. **提交计划**：调用 exit_plan_mode 工具，参数：
   - title：≤20 字
   - summary：≤150 字
   - steps：至少 3 步，复杂任务 5-8 步，每步含：
     - id：步骤 ID
     - content：详细描述，必须包含 ①做什么 ②为什么 ③关键参数/阈值。长度 30-100 字
     - tool：（可选）将使用的工具名

### 📝 步骤详细度规范（重要！）

**❌ 错误示例（禁止）**：
step1: 检查温度
step2: 调节通风
step3: 通知用户

**✅ 正确示例（详尽可执行）**：
step1: 查询过去24小时1号棚温湿度趋势（get_sensor_history），判断是否超出生理阈值（昼25°C/夜18°C，湿度75%）。

step3: 若湿度>80%，延长通风时长至每日6小时，预防灰霉病高发。
step4: 创建每日8点定时巡检任务（cron_create），持续一周。
step5: 通过 ask_user_question 向用户确认是否需要增施磷钾肥。

### 🔄 行为规范
1. 进入计划模式后不要执行任何有副作用操作
2. 提交计划后立即停止，等待用户审批
3. 用户批准后按步骤执行
4. 用户可能修改计划，必须按修改后的步骤执行
5. 用户拒绝后停止任务
6. 简单任务不要用计划模式
7. 不要与 ask_user_question 同时使用
8. steps 数组至少 3 步
```

## 8. Agent Loop 与工具体系

### 8.1 Agent Loop（ReAct 多轮循环）

**文件**：`app/api/chat/route.ts` 第 1360+ 行

```
MAX_AGENT_ITERATIONS = 5

循环逻辑：
1. 发送请求（含 tools 定义）给 LLM
2. 若 LLM 返回 tool_calls → 执行工具 → 将结果加入 messages → 继续循环
3. 若 LLM 返回 content（无 tool_calls）→ 结束循环
4. 若达到 MAX_ITERATIONS → 强制要求 LLM 生成最终回答

特殊中断条件：
- hasClarifyAction：ask_user_question 工具触发 → break，等用户回复
- hasPlanSubmitAction：exit_plan_mode 工具触发 → break，等用户审批
```

|------|------------------|----------------|
| ask_user_question | 'clarify' | 注入 `<CLARIFY>` 标签 + break loop |
| exit_plan_mode | 'exit_plan_mode' | 注入 `<PLAN>` 标签 + break loop |
| enter_plan_mode | 'enter_plan_mode' | 设置 planMode=true，继续调研 |

**关键修复**：注入的标签内容必须通过 SSE 推送给前端，否则前端收不到标签无法渲染卡片。

## 9. Plan Mode（计划模式）

### 9.1 两种进入方式

1. **用户手动启用**：前端切换器开启 `enablePlanning` → 请求体传给后端 → `planMode = true` 初始化 → 附加 planModeHint
2. **AI 自主调用**：AI 调用 `enter_plan_mode` 工具 → Agent Loop 设置 `planMode = true`

### 9.2 计划模式工具过滤

计划模式下屏蔽 7 个有副作用工具：

```typescript
const PLAN_MODE_BLOCKED_TOOLS = new Set([
  'toggle_relay', 'set_led', 'control_camera', 'reset_camera',
  'cron_create', 'task_create', 'task_update',
])
```

### 9.3 计划审批流程

```
AI 调用 exit_plan_mode 
  → Agent Loop 注入 <PLAN>{json}</PLAN> 到 content
  → SSE 推送给前端
  → break loop
  → 前端渲染 PlanApprovalCard
  → 用户预览/编辑/批准/拒绝
  → 用户批准 → onSendMessage("【计划批准】...") → AI 按步骤执行
  → 用户拒绝 → onSendMessage("【计划拒绝】...") → AI 停止
```

### 9.4 PlanApprovalCard 组件

**文件**：`components/ai/plan-approval-card.tsx`

- **预览模式**（默认）：只读展示标题、摘要、步骤
- **编辑模式**：可修改标题、摘要、步骤内容；增删步骤；调整顺序
- 批准时若处于编辑模式，传回修改后的完整计划给 AI

## 附：完整 Prompt 组装顺序（伪代码）

```typescript
// 1. 基础 prompt
let enhancedSystemPrompt = systemPrompt  // 来自用户设置
  + '\n\n' + skillContent                // 智能路由选中的技能

// 2. Persona 注入（最高优先级，放最前）
if (persona) {
  enhancedSystemPrompt = getPersonaPrompt(persona) + '\n\n' + enhancedSystemPrompt
}

// 3. 记忆增强
enhancedSystemPrompt = await generateMemoryEnhancedPrompt(enhancedSystemPrompt, {
  userId, includePreferences: true, includeDevicePatterns: true, includeStrategies: true
})

// 4. 静态段
const staticBasePrompt = enhancedSystemPrompt
  + (needsReportInstruction ? reportInstructionFull : reportInstructionShort)
  + capabilitiesInstructionText

// 5. Compact 指令注入（generateCompactSystemPrompt）
const compactPrompt = generateCompactSystemPrompt({
  basePrompt: staticBasePrompt,
  enableDeviceControl, enableReasoning, mcpToolNames, contextCompressed, aiFeatures,
  includeScheduleTaskDetail: needsFullScheduleDetail
})
// 内部按顺序：禁用警告 → basePrompt → 定时任务 → 设备控制 → 视觉巡检 → 思维链
//           → 引用规范 → 知识库 → 工具规范 → MCP工具 → 上下文说明
//           → TASK_LIST → CHECKPOINT → CLARIFY → PLAN_MODE → 可用UI标签

// 6. 动态段
const planModeHint = enablePlanning ? '【用户已手动启用计划模式】...' : ''
const dynamicSuffix = contextInfo  // 时间/设备状态/天气/定时任务/摄像头
  + forcedToolPrompt               // @提及强制/搜索意图强制
  + planModeHint

// 7. 最终 prompt
const finalSystemPrompt = compactPrompt + dynamicSuffix
```
