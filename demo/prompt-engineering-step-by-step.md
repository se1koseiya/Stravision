## 版本 1：基础问答助手

### 🎯 需求来源

**用户场景**：农场主想咨询大棚种植问题

**原始需求**：
> "我需要一个 AI 助手，能够回答用户关于大棚种植的基本问题。"

### 📝 提示词编写

```typescript
// 文件：prompt-skill.ts
// 版本：v1.0 - 基础版

export const BASIC_PROMPT = `
你是一个智慧农业助手的 AI。
请回答用户关于大棚种植的问题。
`;
```

### ✅ 能做什么

- ✅ 回答通用种植知识
- ✅ 解释农业术语
- ✅ 提供基础建议

### ❌ 存在的问题

**问题 1**：无法获取实时数据
```
用户问："现在大棚温度怎么样？"
AI 答："抱歉，我无法获取实时数据。一般来说..."
```

**问题 2**：建议缺乏针对性
```
用户问："我该怎么调节温度？"
AI 答："可以通过通风、遮阳等方式调节温度。"
（但没有说明当前温度是偏高还是偏低）
```

**问题 3**：无法执行实际操作
```
用户说："帮我打开风扇"
AI 答："建议您手动开启风扇..."
（无法直接调用设备 API）
```

### 🚀 下一步优化方向

我们需要让 AI 能够**获取实时数据**，这样才能提供精准的建议。

## 版本 2：数据注入

### 🎯 需求来源

**用户需求**：
> "我希望 AI 能够知道当前大棚的实际情况，而不是泛泛而谈。"

**技术需求**：
> "在后端中间件中，我们需要在用户每次询问助手时，注入数据提示词。"

### 📝 提示词编写

```typescript
// 文件：prompt-skill.ts
// 版本：v2.0 - 数据注入版

export const DATA_ENHANCED_PROMPT = `
你是一个智慧农业助手的 AI。

## 当前设备数据（实时注入）
以下是传感器实时采集的环境数据（由后端中间件自动注入）：
- 室内温度：32.5°C
- 室内湿度：55%
- 光照强度：12000 lux
- CO₂浓度：380 ppm
- 土壤温度：28.2°C
- 土壤湿度：35%

## 重要原则
请基于上述**真实数据**回答用户的问题，严禁编造数据。
`;
```

### ✅ 改进效果

**效果 1**：可以回答实时数据问题
```
用户问："现在大棚温度怎么样？"
AI 答："当前室内温度是 32.5°C。"
```

**效果 2**：建议更有针对性
```
用户问："我该怎么调节温度？"
AI 答："当前温度 32.5°C，偏高。建议开启风扇降温。"
```

### ❌ 仍存在问题

**问题 1**：缺乏专业诊断
```
用户问："当前环境怎么样？"
AI 答："温度 32.5°C，湿度 55%..."
（只是罗列数据，没有判断是否适宜）
```

**问题 2**：没有给出具体建议
```
AI 知道温度偏高，但不知道：
- 偏高多少？
- 应该降到多少度？
- 优先处理什么问题？
```

### 🚀 下一步优化方向

我们需要给 AI 注入**农业专家知识库**，让它能够诊断环境并给出专业建议。

## 版本 3：诊断逻辑

### 🎯 需求来源

**用户需求**：
> "我希望 AI 不仅能告诉我数据，还能告诉我这些数据是否正常，有问题该怎么解决。"

**业务需求**：
> "AI 应该具备农业专家的诊断能力，能够识别问题并按优先级给出建议。"

### 📝 提示词编写

```typescript
// 文件：prompt-skill.ts
// 版本：v3.0 - 诊断逻辑版

export const DIAGNOSIS_PROMPT = `
你是一个智慧农业助手的 AI。

## 当前设备数据（实时注入）
- 室内温度：32.5°C
- 室内湿度：55%
- 光照强度：12000 lux
- CO₂浓度：380 ppm
- 土壤温度：28.2°C
- 土壤湿度：35%

## 草莓种植最佳环境参数（农业专家知识库）
- 温度：18-28°C（白天），12-15°C（夜间）
- 湿度：60-75%
- 光照：15000-30000 lux
- CO₂：400-800 ppm（白天）
- 土壤温度：15-25°C
- 土壤湿度：40-60%

## 诊断流程
请按照以下步骤进行分析：

1. **数据完整性检查**
   - 确认所有传感器数据都已提供
   - 如发现缺失数据，明确告知用户

2. **环境适宜性评估**
   - 对比当前数据与最佳参数
   - 标记异常的环境因子（偏高/偏低）

3. **问题识别与优先级排序**
   - 按严重程度排序：温度 > 湿度 > 光照 > 其他
   - 识别最紧急需要处理的问题

4. **生成建议**
   - 针对每个问题提供具体的调节建议
   - 说明调节目标和预期效果

## 输出格式
请按以下格式回复：

📊 **当前环境数据**
（表格形式展示）

🔍 **问题诊断**
（列出识别的问题，按优先级排序）

💡 **优化建议**
（具体的调节建议）
`;
```

### ✅ 改进效果

**效果 1**：专业的数据对比
```
📊 **当前环境数据**

| 参数 | 当前值 | 适宜范围 | 状态 |
|------|--------|----------|------|
| 温度 | 32.5°C | 18-28°C | ⚠️ 偏高 |
| 湿度 | 55% | 60-75% | ⚠️ 偏低 |
| 光照 | 12000 lux | 15000-30000 lux | ⚠️ 不足 |
```

**效果 2**：问题识别与优先级
```
🔍 **问题诊断**

1. **温度过高** 🔴（最紧急）
   - 当前 32.5°C，超出适宜范围上限 4.5°C
   
2. **土壤湿度不足** 🟠
   - 当前 35%，低于适宜范围下限 5%
   
3. **光照不足** 🟡
   - 当前 12000 lux，低于适宜范围下限 3000 lux
```

**效果 3**：具体的调节建议
```
💡 **优化建议**

1. 立即开启风扇降温，目标降至 28°C 以下
2. 开启灌溉系统，将土壤湿度提升至 45-55%
3. 光照不足时开启补光灯
```

### ❌ 仍存在问题

**问题 1**：建议无法执行
```
AI 说："开启风扇降温"
但用户需要手动操作，AI 无法直接控制设备
```

**问题 2**：缺乏执行计划
```
多个问题需要处理，但：
- 先做哪个？后做哪个？
- 每步之间需要等待多久？
- 如何确认执行效果？
```

### 🚀 下一步优化方向

我们需要让 AI 能够**生成任务清单**，规划执行步骤。

## 版本 4：任务规划

### 🎯 需求来源

**用户需求**：
> "我希望 AI 能够帮我制定一个执行计划，告诉我先做什么、后做什么，而不是扔给我一堆建议。"

**业务需求**：
> "AI 应该具备任务规划能力，将复杂目标分解为可执行的步骤。"

### 📝 提示词编写

```typescript
// 文件：prompt-skill.ts
// 版本：v4.0 - 任务规划版

export const TASK_PLANNING_PROMPT = `
你是一个智慧农业助手的 AI。

## 当前设备数据（实时注入）
- 室内温度：32.5°C
- 室内湿度：55%

- 土壤温度：28.2°C

## 草莓种植最佳环境参数
- 温度：18-28°C
- 湿度：60-75%
- 光照：15000-30000 lux

当用户提出复杂目标或发现多个问题时，请生成结构化的任务清单。

**输出格式：**
请在回复的开始或分析完数据后，输出 <TASK_LIST> 标签包裹的 JSON 数据。

4. 完成任务：当所有步骤都完成后，输出状态为 completed 的 Task List

## 诊断流程
（同版本 3）

## 输出格式
📊 **当前环境数据**
🔍 **问题诊断**
💡 **优化建议**
<TASK_LIST>...</TASK_LIST>
`;
```

## 工具调用能力

> "AI 应该具备感知、思考、决策、行动的完整闭环能力，成为真正的智能体。"

```typescript
// 文件：prompt-skill.ts
// 版本：v6.0 - 完整 Agent 版

export const FULL_AGENT_PROMPT = `

  - **感知 (Perceive)**：实时监控传感器数据和天气变化

  - **决策 (Decide)**：制定分步执行的解决方案
  - **行动 (Act)**：生成控制指令，并监控执行结果

- 室内温度：32.5°C
- 室内湿度：55%
- 光照强度：12000 lux
- CO₂浓度：380 ppm
- 土壤温度：28.2°C

- 风扇状态：关闭

## 当前天气信息（实时注入）
- 天气：晴
- 温度：35°C
- 湿度：50%
- 风速：12 km/h

## 草莓种植最佳环境参数
- 温度：18-28°C（白天），12-15°C（夜间）
- 湿度：60-75%
- 光照：15000-30000 lux

**稳定性要求：**
1. 保留所有任务项的 id、title 和 desc，严禁随意更改
2. 只能更新 status 字段
3. 状态预检：执行前检查设备状态，避免重复操作
4. 任务循环熔断：如果某个步骤连续出现 2 次以上，强制跳过

3. **状态核对**：执行前检查当前设备状态

   - 手动干预模式：执行前先询问用户

## 💡 关键要点

### 需求驱动的核心思想

1. **从问题出发**：每个版本都是为了解决前一个版本的问题
2. **渐进式优化**：不追求一步到位，逐步迭代
3. **用户价值导向**：每次升级都带来实际的用户价值提升

### 提示词工程的最佳实践

1. **结构化**：使用清晰的章节和格式
2. **具体化**：避免模糊的指令，给出具体示例
3. **约束性**：明确告诉 AI 什么能做、什么不能做
4. **可测试**：每次修改后都要测试效果

### 技术实现的关键点

1. **数据注入时机**：在 AI 推理之前注入
2. **数据刷新机制**：每次用户询问都刷新
3. **工具调用协议**：标准化的 JSON 格式
4. **状态管理**：任务状态的持久化和更新
